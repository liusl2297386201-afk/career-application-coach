# Complete JD Application Case

Use this whenever the user provides both a resume and a JD, unless they explicitly request a narrowly scoped answer. Deliver a complete `baseline application case v0` before asking questions.

## Stage A: baseline application case v0

### 1. Role mechanism and 30-second judgment

State the business problem the role exists to solve, the level of ownership it expects, and one of: `apply`, `apply selectively`, or `do not prioritise yet`. Name the strongest angle and the earliest real screening risk. Do not treat an unusual experience as a risk merely because it is unusual.

### 2. 岗位所需能力拆解

Classify requirements by business importance:

- `hard`: likely screen-out conditions such as seniority, degree, location, language, required domain, or mandatory project history;
- `core`: recurring work and result responsibility the role must deliver;
- `preferred`: differentiated but nonessential evidence;
- `implicit`: a reasoned expectation inferred from the role, visibly labelled;
- `risk`: ambiguity or potential mismatch that needs validation.

Summarise the target candidate in one sentence: not a pile of keywords, but the decisions, collaborators, and outcomes they must reliably own.

### 3. 岗位与经历匹配度

Map every `hard` and `core` requirement, plus the material preferred signals. Use this exact logic:

`JD requirement -> source fact -> demonstrated capability -> match status -> evidence strength -> resume emphasis -> likely interview follow-up`

Use only four statuses:

- `direct match`: the source shows the same work mechanism or result responsibility;
- `transferable match`: the underlying mechanism transfers, but context, scale, or ownership differs;
- `evidence insufficient`: the material does not establish the requirement; do not treat it as absence of experience;
- `hard gap`: a stated requirement is currently unmet or cannot truthfully be claimed.

Do not use keyword overlap as a match. Explain why the work mechanism matches or differs.

### 4. Select and reconstruct the core cases

Select two or three cases by relevance, ownership, rarity, and evidence quality—not employer prestige. For each case, use the known-fact STAR structure from [star-interview.md](star-interview.md). Show a concise `case thesis`: what this case proves for this JD, what it does not prove, and which existing module or metric must remain visible.

### 5. 简历改写建议

State first what must remain untouched. Then recommend only the smallest edits that create a visible gain for this JD. A candidate edit must retain source value units and identify its revision gain. Do not output a full replacement resume by default; provide one only when requested or after the user confirms the relevant candidate modules.

### 6. 经历追问，提炼精华

Use [star-interview.md](star-interview.md). Provide 12 questions across project deep-dives, role-professional questions, and behavioural/career questions. For each, state the source of the question and the evidence already available. Do not invent model answers.

### 7. Give the portfolio-case plan

Use [portfolio-case.md](portfolio-case.md). Identify the best two or three cases, what each must prove, available evidence, materials to collect, and confidentiality boundaries. If an optional public-data simulation would help, label it as a simulation rather than a work result.

### 8. 职业路径规划&近期行动目标

Use [decision-action.md](decision-action.md). Give a primary path, one adjacent path, confirmed capabilities, the key evidence gap, and a 30/60/90-day validation plan. Keep this to the immediate career decision; do not imitate a full long-term planning report.

## 补充说明

Only after all eight baseline sections, introduce the following sentence exactly:

`补充回答以下追问，不会推翻上面的 v0，只会帮助完善 v0 的分析内容。`

Ask three to five questions at most. Every question must include:

`question -> why it matters -> exact v0 item it would change`

Prioritise a concrete decision, trade-off, delivery object, affected party, result, repeatable method, or project boundary. Do not ask for a number merely because a template expects one. Do not ask for facts already known. If the user declines or lacks a fact, keep the v0 judgment and mark the evidence boundary.

## Stage C: upgraded case v1

After the answer, update only the affected matrix rows, STAR fields, candidate edits, interview answers, portfolio materials, and action card. Make the delta visible. Never silently replace the original resume.

## PDF choice

After presenting a complete v0 or upgraded version, ask exactly: `是否需要我将该版内容整理为 PDF输出？（若不回答该问题则默认不需要）` Do not create an HTML page. Create a PDF only after an explicit yes, and include the complete current report rather than only selected excerpts. If the user does not answer the question, treat that as not needing a PDF and do not repeat the question for the same version.
