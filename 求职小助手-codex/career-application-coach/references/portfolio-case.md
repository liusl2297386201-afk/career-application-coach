# Portfolio Case Planning

Use as part of a complete application case when a role rewards visible project evidence. Plan evidence-led cases, not a longer visual resume.

## Choose cases

Select two or three cases that jointly demonstrate the target role's most important mechanisms. For each state:

`case thesis -> role capability proved -> direct evidence available -> material to collect -> confidentiality boundary -> interview question it supports`

Prefer a concise PDF or case deck. One case should not claim to prove every competency.

## Page structure

Use two or three pages per case:

1. `Context and objective`: business setting, user or audience, problem, role boundary, and desired result.
2. `Judgment and mechanism`: insight, alternative considered if known, decision, execution mechanism, collaborators, and key outputs.
3. `Evidence and result`: screenshots or artefacts, data with scope, user/partner effect, reflection, and next improvement.

Use a conclusion as the page title and images as evidence. Redact confidential names, unreleased assets, private data, and personal information. Do not publish raw internal files when a cropped or reconstructed diagram can prove the same fact.

## Simulations

If a material gap is important, an optional public-data simulation may show thinking. It must be marked `simulation based on public information`, distinguish assumptions from facts, and never report fictional results, budget, conversion, or partnership ownership.
