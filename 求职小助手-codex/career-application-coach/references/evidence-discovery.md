# Evidence Discovery and Project Boundaries

Use when material is fragmented, the user cannot yet name their strengths, or actions and results blur across projects. Do not begin with a long questionnaire.

## Source boundary

- `direct evidence`: user-authored resume, work document, review, report, note, or explicit user statement.
- `user-confirmed evidence`: a fact the user confirms in the conversation.
- `secondary material`: AI suggestions, templates, or speculative plans. Never promote this into a work fact.

Treat title, employer, date, education, and project identity as source-controlled. Never silently rename or merge them.

## Give a provisional case before dialogue

First return a project-boundary map with each independent work line: context, role, time if known, objective, actions, collaborators, delivery objects, and results. Then state confirmed strengths, provisional target directions, and the highest-value evidence gaps. This is the user's first useful result.

## Ask in progressive layers

Ask only one to three questions in a turn and explain what each will clarify.

1. `Boundary`: Which project did this action or result belong to? What was the user's actual role?
2. `Decision`: What problem, constraint, comparison, or trade-off led to the chosen approach?
3. `Value`: What was delivered, who used it, what changed, and what can demonstrate that change?
4. `Repeatability`: What principle or method could be applied again, and where would it fail?

Reflect the strengthened finding before the next question. Do not collect a permanent archive unless the user asks for one.
