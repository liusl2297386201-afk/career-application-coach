# Lossless Experience Rewrite

Use whenever the user asks to strengthen existing wording and has not asked for compression.

## Extract before drafting

Preserve every nonduplicated value unit:

`business context | objective | judgment or constraint | action | collaborator | delivery object | platform/tool | scope | mechanism | metric | result`

Keep meaningful original subheadings and module boundaries. Do not replace real detail with generic verbs such as “coordinate”, “drive”, or “ensure” unless the detail remains visible.

## Use STAR internally, not decoratively

Reconstruct the source internally as:

`Situation: context or challenge -> Task: role and objective -> Action: decisions, trade-offs, delivery and collaboration -> Result: metric or observable change`

If a STAR element is absent, label it `needs confirmation`; do not invent it. Bring only the causal chain needed by the target role into the final bullet:

`scenario -> judgment or goal -> specific action and delivery/mechanism -> result`

## Candidate revision format

For each affected module show:

- `source value units retained`;
- `internal STAR status`: known facts and evidence to confirm;
- `candidate wording`;
- `revision gain`: `retained source fact -> newly legible capability -> target relevance`.

If no concrete gain exists, recommend retaining the original. A shorter sentence is never a sufficient gain.

## Compression is separate

Prune or merge only when the user explicitly asks for a one-page version, a length limit, or removal of weak material. Explain each removal; never silently discard valuable evidence.
