# China Game Publishing Rewrite

Use this reference for mainland China game-publishing, content-publishing, community, streamer/creator, and Steam/indie-game roles.

## Judge differentiated evidence, not prestige alone

Do not make a major-company internship the default lead merely because of its name. Compare direct evidence for scope, ownership, rarity, current relevance, and target-role relevance. A long-running IP project, a game-project role, and a publisher internship can each be core evidence for different reasons.

Do not require product name, genre, audience profile, attribution detail, or more metrics in a resume body unless the JD or source ambiguity makes it necessary. Treat those facts as interview-preparation prompts by default.

## Keep module-level proof visible

Explicit subheadings such as content distribution, community operations, and livestream/event operations demonstrate different capabilities. Retain that separation unless the user requests a different structure.

Translate facts without deleting them:

| Source evidence | Capability made legible |
| --- | --- |
| player/user research, topic choice, scripts, videos, results | audience insight to content strategy and measurable content delivery |
| IP worldbuilding, persona, visual style | zero-to-one content/IP expression |
| artists/designers/PV creators, briefs, review | creator capacity and content-asset delivery |
| livestream setup and content presentation | final livestream-content execution |
| community feedback, bugs, sentiment | launch-period player-signal and community maintenance |
| streamer recruitment, reward rules, UGC | creator/player activation mechanism |
| Steam and multi-platform publicity data | multi-platform release execution |
| R&D/art/program coordination, prototypes, acceptance | development-to-publishing delivery coordination |

This map helps interpretation. It does not permit unsupported claims of budget ownership, paid acquisition, revenue impact, overall growth ownership, or campaign leadership.
